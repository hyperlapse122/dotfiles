# AGENTS.md

This is the repository supplement for `github.com/hyperlapse122/dotfiles` checkout source state only. Edit this checkout, never deployed `$HOME`; apply only when the user asks for deployment. The common machine-wide user instructions are defined in `.chezmoitemplates/agents-instructions.tmpl` (which renders to `~/.omp/agent/AGENTS.md`); edit that template when modifying global instructions. This file defines repository-specific Chezmoi attributes, script lifecycles, host fact gates, system manifests, and verification workflows.

## Source layout and attributes

Chezmoi source names encode targets: `dot_foo` -> `~/.foo`, `*.tmpl` is rendered, `private_` is 0600, `readonly_` is 0444, `executable_` is executable, `encrypted_*.asc` is gpg ciphertext, `.chezmoiscripts/run_once_*` runs once ever, `.chezmoiscripts/run_onchange_*` reruns when rendered content changes, `.chezmoiscripts/run_after_*` runs every apply, `.chezmoidata` is data, `.chezmoitemplates` is shared template code, `.chezmoiexternals` is fetched tooling, and `.chezmoiignore` is templated exclusion. Dot-prefixed source paths are internal; non-dot metadata (`AGENTS.md`, `LICENSE`) MUST be listed in the root `.chezmoiignore`. `crates/` and `packages/` are source-only build trees. `docs/` is repo-meta and never deployed: `docs/plans/` holds work plans, and `docs/solutions/` holds documented solutions to past problems (bugs, practices, workflow patterns) filed by category with YAML frontmatter (`module`, `component`, `problem_type`, `tags`) — relevant when implementing or debugging in an area one of them already covers.

Edit source files, not deployed files. The source directory itself is the only valid source context; nested worktrees cause recursive data errors, so checks MUST use `--source "$PWD"`. Never commit secrets.

## Apply lifecycle and script tree

Prefer `run_onchange_before_`/`run_onchange_after_` with a comment-only dependency fingerprint over unconditional `run_after_`. Keep bare `run_after_` only when live state must be retried on every apply. Fingerprint raw source content, including unresolved `op://` refs, never rendered secrets or build output. The shared `.chezmoitemplates/fingerprint.tmpl` contract is:

```gotemplate
{{ $sourceDir := .chezmoi.sourceDir -}}
{{ includeTemplate "fingerprint.tmpl" (dict "sourceDir" $sourceDir "globs" (list "path/to/source" "other/**")) }}
```

The partial hashes file content, uses `(stat .).isDir` to skip directories/output directories, and MUST NOT hash a rendered secret. A script with no external dependency hashes only its own rendered content; document that explicitly. A clean exit-0 skip is recorded as successful and will not retry until a fingerprint changes or `chezmoi apply --force` is used; retain `run_after_` only when that retry behavior is essential.
Script early exits MUST declare one of three skip directions: `harmless` (this host will never satisfy the condition, so not acting is correct and final), `transient-tolerable` (an eligible host is missing a precondition and failing here cannot block later chezmoi phases), or `transient-blocking` (an eligible host is missing a precondition, but failing here would abort later phases, so it exits 0 behind a declared capability probe instead). Script early exits MUST use `.chezmoitemplates/skip.sh.tmpl` declarations across its four call forms (`skip_here`, `skip_step`, `done_here`, `not_applicable`), verified by `.ci/check-skip-declarations.sh`. Run `dotfiles-skips` to list outstanding `transient-tolerable` and `transient-blocking` skips without inspecting apply scrollback; it only reads recorded state, never probes capabilities or hosts and never mutates anything. Bare `exit 0` or `return 0` on conditional script paths is prohibited.


Never add teardown/revert scripts. Delete managed source, use `.chezmoidata/system.yaml` `removed:`, declare an omp plugin in `agents.omp.pluginsRemoved`, or document a one-time manual reversal. A `.chezmoiremove` entry may also prune a runtime-created path chezmoi never deployed; `.agents/skills/ce-*` and `.local/state/unmanaged-repo-guard` are the standing cases. Numeric `.chezmoiscripts/` directories establish phase order; existing `run_*` naming and numeric ordering may be extended, and renaming an onchange script reruns it once per host.

| Directory | Responsibility |

Package installation is owned modularly by feature scripts in `.chezmoiscripts/30-components/` and base installers in `.chezmoiscripts/20-base/`. Package installation scripts MUST always inspect which packages are not yet installed (e.g. `rpm -q` on Fedora, `dpkg-query -W` on Ubuntu, `brew list` on macOS, `dotnet tool list -g` for global .NET tools) and only install missing packages, never blindly passing all declared packages to the package manager unconditionally.

## Host facts, gates, and system configuration

`.chezmoidata/facts.yaml` is the sole host-identity registry: each fact has a type, `hook`/safe template/builtin probe, gates, and fail-safe `whenFalse`. Hook facts are written once per chezmoi command by `.install-prerequisites.sh`; template facts come from `.chezmoitemplates/facts.tmpl`. The hook's `is_container`/`is_devbox` predicate and `facts.tmpl` predicate MUST remain byte-for-byte lockstep: a real container is `/run/.containerenv` or `/.dockerenv` without `/run/.toolboxenv`; distrobox/toolbox is treated as the host. `jetson` is a template fact. It probes `/etc/nv_tegra_release`. `sharedHost` is a template fact. Its gate is true when `/etc/dotfiles-shared-host` exists, `jetson` is true, or `.chezmoi.username` contains `@`.

Gate grammar is `<fact>`, `!<fact>`, or `<fact>.<value>`; YAML values beginning `!` MUST be quoted. `facts-validate.tmpl` rejects unknown facts, missing probes, invalid comparisons, malformed desktop values, and undeclared emitted facts. Consumers use only `facts.tmpl`, `facts-sh.tmpl`, and `facts-gate.sh.tmpl`, never the cache. Every fact is render-time and fail-safe: false MUST skip rather than grant. `FORCE_NVIDIA` is an installer-only override, never a fact or system-file gate; `INSTALL_SYSTEM_CONFIG_FORCE` layers only on the headless guard. `stat` is required before absolute `include`; `glob` does not traverse symlinks; never use template `output` for a fact probe. Runtime scripts call shared `fact_gate()` and MUST NOT duplicate gate logic.

`system/linux/etc/**` mirrors `/etc`; `.chezmoidata/system.yaml` owns mode, gate, check, distro-scoped `removed:`, and reload behavior. Edit the manifest and tree, not installers. The modular `install-system-*` installers have independent onchange triggers. Reload only changed services; Bluetooth restarts only when Bluetooth files differ. Network changes can reload firewalld. The 30-network installer defers its explicit activation of resolved, NetworkManager, and Tailscale until manual restart or reboot. GDM greeter fingerprint login MUST remain disabled while in-session fingerprint remains available. Polkit may add `pam_fprintd` only when the Debian `common-auth` conjunction is true; MUST NOT use `pam-auth-update` or a `common-auth` integration for fingerprint support, because it would re-enable greeter fingerprint authentication and break the GDM/Fedora polkit boundary. Sudo remains password-only. Fcitx5 is the KDE/GNOME input method; the GNOME autostart entry MUST NOT add `X-GNOME-Autostart-Phase`. TPM2 uses the shared dracut/systemd-cryptenroll backend and blank/missing credentials skip. Plymouth remains distro-native; SDDM Breeze is gated on its installed theme. On Ubuntu, a username with `@` is authd-managed. The login-shell script uses `authctl user set-shell` only when that exact subcommand exists. Otherwise, it makes a schema-checked `sqlite3` update to the authd database. Never use Python. Never restart the authd daemon.

## Agent surfaces and ownership

All agent data is in `.chezmoidata/agents.yaml`. The managed harness set comprises `claude` (Claude Code), `agy` (Google Antigravity CLI), and `omp` (Oh My Pi). MCP declarations in `agents.mcp.servers` are transport-neutral and render into universal `~/.mcp.json` as well as harness-specific configurations (`~/.gemini/config/mcp_config.json`, `~/.omp/agent/mcp.json`), with 1Password `op://` references resolved at apply time. OAuth entries stay headerless for native stores. Figma authorization is on demand through `figma-auth`; never commit tokens.

External skills come from `agents.skills.external` -> `.chezmoiexternals/ai-agents.toml` -> `~/.agents/skills/<name>`; keep the exact isolated subtree and no pin-bump workflow. GitHub-sourced skills (`agent-browser`, `improve`, `i-have-adhd`, `composition-patterns`, etc.) ship as archive externals extracting the `skills/<name>/` subtree. GitLab-sourced skills (`glab`, `glab-stack`) are raw single-file externals (`type = "file"` on `<name>/SKILL.md`) pinned to the glab release via `.chezmoitemplates/glab-release-ref.tmpl`, which `.chezmoiexternals/vcs.toml`'s glab binary also consumes. Locally-authored personal skills (unpublished) are managed directly under `dot_agents/skills/<name>/` and deploy to `~/.agents/skills/<name>`. `dot_agents/skills/` is harness-neutral; chezmoi deploys symbolic links `~/.claude/skills` and `~/.gemini/skills` pointing to `~/.agents/skills` to ensure unified skill discovery across all harnesses.

External Agent Plugins (agent-plugins.org v1.0.0 standard packages containing plugin.json, skills/, mcp.json) come from `agents.agentPlugins.external` -> `.chezmoiexternals/ai-agents.toml` -> `~/.local/share/omp-plugins/plugins/<name>`. They are automatically included in the local `h82-dotfiles` marketplace catalog (`dot_local/share/omp-plugins/dot_omp-plugin/marketplace.json.tmpl`), allowing OMP to load and validate them through the marketplace reconciler without violating realpath containment.

Compound-engineering is one versioned local archive owned by the neutral `agents.marketplaces` registry; omp consumes it.

SELinux Type Enforcement on Fedora (`system/linux/selinux/dotfiles_protected_agent_configs.cil`) protects all agent configurations (`~/.claude/settings.json`, `~/.claude.json*`, `~/.mcp.json`, `~/.gemini/config/mcp_config.json`, `~/.codex/config.toml`), skill directories (`~/.agents/skills/`, `~/.agents/plugins/`), and symlinks from accidental non-chezmoi writes or mutations: `unconfined_t` retains full read-only access while write, delete, and relabel operations are restricted exclusively to `chezmoi_t`.
An agent config file moves to per-key assertion when its vendor writes it during normal use and stays managed-readonly otherwise. omp's `config.yml` is on the assertion side. It is NOT a chezmoi target because omp rewrites it through `/model`, `/settings`, and first-run setup. `run_after_config-omp-settings.sh.tmpl` asserts each declared `agents.omp.settings` path into it on every apply and leaves every undeclared path to omp. A declared record-typed path is owned wholesale because `omp config set` replaces a record and rejects a path inside one. A declared `null` instead resets the path to omp's upstream default via `omp config reset`; convergence reads an unset key's missing `value` in the live listing, so null is valid only for empty-default keys, and `omp-settings-validate.tmpl` rejects null fail-closed on record- and list-typed paths. Declared omp settings MUST stay credential-free because that CLI receives values as process arguments. Credentials are declared under `agents.omp.auth.env` and reconciled as a closed set into its private `.env`; OAuth stays in `agent.db`. Retiring the old config target deliberately left the deployed file in place, so it has no `.chezmoiremove` line or `remove_` source. omp's `models.yml`, MCP file, and instructions stay managed-readonly. `~/.omp/agent/mcp.json` remains managed-readonly as a dated exception (2026-07-29) until per-key assertion covers a list-shaped target.

Repo-scoped agent tooling is a separate category from those user-scoped skills. `.agents/skills/<name>/SKILL.md` at the repository root would be a PROJECT skill for agents working in this checkout, discovered by omp's native `agents` provider (`enableAgentsProject`, oh-my-pi `docs/skills.md`). Such a path is dot-prefixed, so chezmoi treats it as internal source and never deploys it, and it MUST NOT be confused with `dot_agents/skills/<name>/`, the user-scoped personal-skill source that DOES deploy to `~/.agents/skills/<name>`. Model policy is governed by the data and its gates, not by a skill — see `.chezmoidata/agents.yaml` and `.chezmoitemplates/omp-settings-validate.tmpl`.

OMP keeps the Codex-user and Claude-user/project compatibility skill providers disabled so they do not duplicate the canonical `~/.agents/skills/` and repository `.agents/skills/` roots. Its structural-search and computer-control tools stay explicitly enabled in `agents.omp.settings`; do not rely on upstream defaults for either capability.

Tool approval is declared for the same reason: `agents.omp.settings` sets `tools.approvalMode: yolo` even though that is omp's current schema default, so a future upstream default change is visible as a data diff rather than a silent behavior change. `tools.approval: {}` is the load-bearing half. In `yolo` a per-tool `deny` or `prompt` is the only policy that still stops a call, and a headless subagent cannot answer a prompt, so a stray `prompt` entry rejects that tool outright instead of pausing. Declaring the record owns it wholesale, so any per-tool policy written into `config.yml` after an apply is cleared on the next one; a deliberate per-tool prompt or deny MUST therefore be declared in the data, never set interactively. `bash.patterns` stays undeclared because `yolo` already ignores a bare critical-command override, so no rule set is needed to reach allow-all. The bundled subagents' own tool lists are a different surface and are deliberately untouched: `scout` (`read, grep, glob, web_search`), `security-reviewer` (`read, grep, glob, lsp, ast_grep`), and `librarian`/`reviewer` (those plus `bash`) carry frontmatter `tools` that no setting overrides — `task.*` exposes only `disabledAgents`, `agentModelOverrides`, `agentPrewalk`, and `agentAdvisor`.

`agents.omp.settings.disabledProviders` is the provider availability gate: `zai`, `github-copilot`, `openai-codex`, and `openrouter` remain disabled. `disabledProviders` applies before any credential check, so it removes a backend from all catalog scans and `/model`.

Model placement is declared in `.chezmoidata/agents.yaml` under one rule: usage is subscription-based, so the scarce resources are quota and latency, never per-token price. The main loop is `google-antigravity/gemini-3.7-flash:high` at `default`, with `defaultThinkingLevel: xhigh` tracking it. Custom role `fable: google-antigravity/gemini-3.7-flash:high` serves `plan`. `slow` lands on `google-antigravity/gemini-3.7-flash:high`, `reviewer` on `google-antigravity/gemini-3.1-pro:high`, and `smol` on `google-antigravity/gemini-3.7-flash:high`. Executor seats (`task`, `designer`, `security-reviewer`, `sonic`) use `@worker` (`google-antigravity/gemini-3.7-flash:high`), extraction tiers (`scout`, `librarian`) use `@skim` (`:low`), and background tasks use `tiny` (`google-antigravity/gemini-3.1-flash-lite:minimal`). `task.enableEffort` is `false`. Two family roles (`claude`, `gemini`) exist solely for cross-model review seats. Automatic model fallback is OFF (`retry.fallbackChains: {}`, `retry.usageAwareFallback: false`, and `retry.modelFallback: false`) so turn spend remains attributable to the selected seat.
Managed instruction targets are one file per harness, named for the native filename: `AGENTS.md` and `APPEND_SYSTEM.md` for omp (`dot_omp/private_agent/`). Deleting a managed source stops management but does not prune an already-deployed target; pruning is a separate explicit decision.

`dot_config/tmux/tmux.conf` is the repository's only tmux target, and it exists for omp's inline images inside aoe-managed sessions. Its `allow-passthrough on` and `set-environment -g PI_FORCE_IMAGE_PROTOCOL kitty` are a PAIR: tmux carries no Kitty-graphics handling, so passthrough is what stops it discarding omp's graphics escape, and the forced protocol turns on the Unicode placeholders that let tmux own the image cells. The protocol value MUST NOT move to `environment.d` or `agents.omp.auth.env`. Verification is `.ci/test-tmux-kitty-passthrough.sh`. `.chezmoidata/agents.yaml` declares `agents.aoe."config.toml".tmux` with `status_bar: enabled` and `clipboard: enabled` to prevent aoe's auto-deference when `tmux.conf` is present.
## Verification (never deploy live `$HOME`)

The default check uses a per-user scratch directory, stub `op`, empty config, throwaway destination, and `--source "$PWD"`. The stub must return newline-free secrets when parsing rendered JSON/TOML. Render every changed template/script through `chezmoi execute-template`; scripts are not targets and MUST be compared as rendered text on both sides. Disclose any onchange side effects, especially network/service restarts; the first apply that reruns `install-system-30-network` MUST be performed from a local console, not SSH/Tailscale.

`git diff --check`, `git status`, and a diff limited to the requested scope are required. `chezmoi archive --exclude=encrypted,externals,scripts` may compare extracted target trees, but archive bytes are not comparable by mtime and the archive omits scripts; compare rendered scripts separately and state that blind spot. If local rendering is unavailable, use CI artifacts from `.github/workflows/render-dotfiles.yml` and state the limitation.

```sh
scratch="$HOME/.cache/agent-scratch/chezmoi-op-stub"
mkdir -p "$scratch/bin" "$scratch/target"
: > "$scratch/empty.toml"
printf '#!/usr/bin/env bash\ncase "${1-}" in whoami) printf dummy@example.invalid;; *) printf dummy-secret;; esac\n' > "$scratch/bin/op"
chmod 700 "$scratch/bin/op"
env PATH="$scratch/bin:$PATH" chezmoi --config "$scratch/empty.toml" --source "$PWD" --destination "$scratch/target" execute-template < .chezmoiscripts/70-agents/run_after_config-omp-settings.sh.tmpl
```

## Secrets and encrypted state

Secrets resolve through a live `onepasswordRead` of their `op://` reference at render time, with no cache; the private-key import (`.chezmoiscripts/80-keys/run_once_before_import-gpg-key.sh.tmpl`) bootstraps the GPG key used for `encrypted_` files. The sole sanctioned repository ciphertext is `dot_config/garden/encrypted_readonly_garden.yaml.asc` (GPG); edit the garden via the wrapper (`chezmoi edit ~/.config/garden/garden.yaml`), never commit plaintext. Host LUKS/MOK prompts are AES-encrypted with a key only in the user keyring; read consumers fail soft when unavailable, and only the nonblank prompt path may create a key. Never infer that desktop-mediated `op read` is unavailable from a failed interactive `op whoami`. GitLab PAT setup is data-driven; `auth-glab` remains OAuth fallback.

Standalone release CLIs belong in grouped `.chezmoiexternals/{ai-agents,dev-tools,vcs,k8s,system,fonts}.toml`; language runtimes/registry backends belong in mise. Keep `rust-analyzer` external plus rustup component, use `/usr/bin/python3` for system scripts, and preserve npm/Bun/Yarn/pnpm hardening. A release artifact that REWRITES ITS OWN TREE is the one thing an external MUST NOT deliver, and the Flutter SDK is the standing case: an archive external makes every extracted file part of the target state, while the tool rewrites `.git/objects/info/commit-graph` and deletes and regenerates `version` and `bin/cache/flutter.version.json` on ordinary use, so the next apply asks to overwrite a file that changed since chezmoi wrote it and fails headless on `/dev/tty`. Excluding `.git` does not rescue it — `bin/internal/shared.sh` runs `git -C $FLUTTER_ROOT rev-parse HEAD` on every invocation and aborts without it. Such a tool is installed by its phase script (`.chezmoiscripts/00-tools/run_onchange_after_flutter.sh.tmpl`), which still reads the same lock through `release-lock-ref.tmpl` and verifies the recorded `sha256`, so the no-render-time-resolution rule below is unaffected.

External release resolution lives in the generated `.chezmoidata/releases.json` lock, so a source-state read performs no network I/O; the migration plan was [`docs/plans/2026-07-27-001-refactor-static-release-artifact-lock-plan.md`](docs/plans/2026-07-27-001-refactor-static-release-artifact-lock-plan.md). The lock is machine-generated by `packages/release-lock` and MUST NOT be hand-edited — add a tool to that package's registry instead. `.github/workflows/refresh-release-lock.yml` re-resolves it hourly via `cli.ts --out`, which overlays the resolution onto the committed lock and commits to the default branch only when an entry actually changed — a source that fails to resolve keeps its last committed entry, and the run still fails. Per-platform URLs and checksums come from the GitHub release API's per-asset `digest`, so the refresh never downloads an artifact to hash it. A declared target whose asset the release does not publish is a hard error, never a silent skip; that strictness is what caught `buf` naming its linux arm64 build `aarch64` while darwin and windows use `arm64`. A target upstream genuinely does not build is declared in `emulatedPlatforms`, served by the amd64 artifact under emulation, and marked `emulated: true` in the lock — so an `x86_64` URL under an `arm64` key is deliberate, not a bug. The lock is authoritative: every externals file, shared template, and version-consuming script reads versions, URLs, and digests through `.chezmoitemplates/release-lock-ref.tmpl`, and no template or script may resolve a release at render time (`gitHub*` builtins, `curl`, `git ls-remote`). `onePassword` is a `vendorManifest` vendor. It reads its version from the vendor RSS feed. Its artifact digest is null.

## OS, desktop, and containers

Branch templates on `.chezmoi.os`; Fedora and Ubuntu 24.04 arm64 on a Jetson are managed Linux targets. Ubuntu support is only for the Jetson hardware profile. KDE/GNOME scripts use the desktop fact and soft-skip missing runtime/session tools. GNOME remains stock except data-driven listed exceptions, fonts, fcitx5, and password-only GDM. Do not turn runtime tool presence into a host fact.

A real container is `/run/.containerenv` or `/.dockerenv` without `/run/.toolboxenv`; the `facts.tmpl` and `.install-prerequisites.sh` `is_container`/`is_devbox` predicates MUST stay in lockstep. Containers skip package/system/auth/desktop/haptic provisioning, garden, and the GPG key, but keep CLI dotfiles, `00-tools`, compound-engineering, and omp. No package installation occurs in a container. Change container skips only in the single gated `.chezmoiignore` block, never by editing scripts. `OP_SERVICE_ACCOUNT_TOKEN` is the CI secret path.

## Repository delivery

Remain on the current branch; the common branch/commit/CI rules apply and this supplement may be stricter. Before a commit, verify the branch and Git Flow prefix unless it is the default branch. Keep changes within the requested scope, use lowercase Conventional Commits, and after any push watch both `render-dotfiles.yml` and `ci.yml` to terminal success.
