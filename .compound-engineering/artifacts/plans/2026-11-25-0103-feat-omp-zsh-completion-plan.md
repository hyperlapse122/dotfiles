# omp zsh completion - Plan

## Goal Capsule

- **Objective:** In the owner's zsh sessions, typing `omp` and pressing Tab offers omp's subcommands, flags, model names, and session IDs from the installed CLI, so commands no longer have to be recalled from `omp --help`.
- **Means:** Generate `_omp` from `omp completions zsh` with the pinned `programs.omp.package` and publish it through the existing personal zsh completions fpath (KTD1, KTD2).
- **Authority:** Product Contract R-IDs govern behavior; KTDs govern mechanism; implementation units implement both.
- **Execution profile:** One pull request. `lfg` runs `ce-work`, review, `ce-commit-push-pr`, and CI watch; the owner applies host rebuilds.
- **Stop conditions:** The pinned omp lacks `completions zsh`; build-time generation needs network or a HOME the derivation cannot write; the generated script fails `zsh -n` or compinit; the interactive zsh check cannot run on an available builder.
- **Open blockers:** None.

## Product Contract

### Summary

Add the omp-generated zsh completion function to the existing personal completions package. The derivation emits `_omp` from the pinned omp package, the prezto fpath already loads that directory, and the existing interactive check proves registration.

### Problem Frame

omp is installed on both hosts, but its CLI has no zsh completion function, so Tab after `omp` falls back to file completion and subcommands and flags must be recalled. omp already emits a version-matched completion script; the repository already owns one fpath for personal completions. The gap is wiring, not missing functionality.

### Key Decisions

- KD1. Completion coverage is zsh only. Governs R1, R3. Rationale: zsh is the interactive shell on both hosts; the repository has no managed personal completion path for bash or fish.

### Requirements

**Completion output**

- R1. The personal zsh completions derivation installs `_omp`, generated by the pinned `programs.omp.package` through `omp completions zsh`.
- R2. The derivation's compinit check proves `omp` resolves to `_omp` and the function is defined.

**Shell integration and documentation**

- R3. The interactive zsh check includes `omp` among the completion functions it verifies.
- R4. `docs/shell.md` lists omp among the supplied completion functions and states the current count.

### Scope Boundaries

- Bash and fish completion are out of scope; neither has a managed personal completion path here.
- Profile aliases created by `omp --alias` are out of scope; the generated script covers the `omp` command.
- Upstream omp changes and a vendored copy of the completion script are out of scope.
- omp settings, packaging, and update behavior are unchanged.

## Planning Contract

### Key Technical Decisions

- KTD1. Generate `_omp` at build time from the pinned `programs.omp.package` through `omp completions zsh`, not from a hand-written table or `eval "$(omp completions zsh)"` at shell startup. Governs R1. Rationale: upstream derives the script from the live command registry, so it stays version-matched; build-time generation keeps shell startup free of an extra process.
- KTD2. Extend `packages/zsh-completions.nix` with an `omp` argument and pass `config.programs.omp.package` from `home/h82/shell/shell.nix`, reusing the existing fpath entry. Governs R1, R2. Rationale: one derivation and one fpath consumer; a second store path or a zsh init snippet adds no behavior and would either duplicate the check or slow every shell.
- KTD3. Add `omp` to both hardcoded completion lists (`packages/zsh-completions.nix` and `tests/zsh-prezto.py`) and update `docs/shell.md` from six to seven. Governs R2, R3, R4. Rationale: the derivation check and the materialized-profile check are the proof; a stale list would let the function disappear without a failure.

### High-Level Technical Design

```mermaid
flowchart LR
  A[pinned omp package] -->|omp completions zsh| B[_omp in the completions derivation]
  B --> C[fpath: share/zsh/site-functions]
  C --> D[compinit: omp -> _omp]
  D --> E[Tab completion in zsh]
```

### Assumptions

- `omp completions zsh` is deterministic, contains no absolute paths, and only needs a writable `HOME`; verified twice against 19.1.1 and with an empty `HOME`.
- The build's existing `HOME=$TMPDIR/home` is sufficient for omp's native-addon extraction.
- The generated script's dynamic `omp __complete` calls resolve the profile's `omp`, which is the same pinned package used for generation.
- The owner uses zsh interactively on both hosts; bash and fish completion is not requested.
- `programs.omp.package` is the installed CLI on both hosts; the module defaults it to the input package and neither host overrides it.
- The generated script is treated as build output, never committed; the package version in `flake.lock` is the source of truth.

### Sources / Research

- `omp completions --help` at 19.1.1 documents the `bash`, `zsh`, and `fish` targets; `omp completions zsh` produced 810 lines beginning with `#compdef omp`, with dynamic `omp __complete` calls for models and sessions.
- The generated output was byte-identical across two runs and contained no store, home, or temporary paths; it generated successfully with an empty `HOME`, which the derivation can provide.
- Repository precedent: `packages/zsh-completions.nix` already generates codex and mise completions and asserts compinit registration; `tests/zsh-prezto.py` asserts the six-command list; `docs/shell.md` states six completions in its parity table and verification paragraph.

## Implementation Units

### U1. Generate `_omp` in the personal completions package

- **Goal:** The completions derivation installs `_omp` generated by the pinned omp package, and its own compinit check registers it.
- **Requirements:** R1, R2. Decisions: KTD1, KTD2.
- **Dependencies:** None.
- **Files:** `packages/zsh-completions.nix`, `home/h82/shell/shell.nix`.
- **Approach:**
  1. Add an `omp` package argument to `packages/zsh-completions.nix`.
  2. Emit `$out/share/zsh/site-functions/_omp` from `${omp}/bin/omp completions zsh`, beside the existing generated functions.
  3. Add `omp` to the derivation's `for completionCommand in ...` compinit check.
  4. Import the package with `omp = config.programs.omp.package` in `home/h82/shell/shell.nix`; the existing fpath line already publishes the directory.
- **Patterns to follow:** the codex and mise generation lines; the derivation's existing writable `HOME`; the fpath wiring in `home/h82/shell/shell.nix`.
- **Test scenarios:**
  - Happy path: the derivation builds, `_omp` starts with `#compdef omp`, and `zsh -n` accepts it.
  - Registration: a clean `compinit` over the output directory maps `omp` to `_omp` and defines the function.
  - Mutation guard: removing the `_omp` generation line fails the derivation check. The check cannot catch removal of its own `omp` loop entry, which is why U2 extends the interactive list.
- **Verification:** build the derivation as part of the materialized profile and see its compinit check pass; the generated file is nonempty and contains no absolute paths.
- **Execution note:** mostly packaging; prefer the derivation's runtime smoke check over adding a unit test.

### U2. Extend the interactive shell check and documentation

- **Goal:** The materialized interactive zsh check covers `omp`, and the shell documentation states seven completions.
- **Requirements:** R3, R4. Decisions: KTD3.
- **Dependencies:** U1.
- **Files:** `tests/zsh-prezto.py`, `docs/shell.md`.
- **Approach:**
  1. Add `omp` to the `for cmd in ...` list in `tests/zsh-prezto.py`.
  2. Update the parity table row and the verification sentence in `docs/shell.md` from six to seven, naming omp in the list.
- **Patterns to follow:** the existing list order and wording in both files.
- **Test scenarios:**
  - Registration: the interactive zsh check passes with the seven-command list; removing `_omp` from the package fails it.
  - Documentation: `docs/shell.md` names all seven functions and contains no stale "six completions" claim.
- **Verification:** the `zsh-prezto` check passes, and `./scripts/agent-check` reports no Markdown or formatting issue.
