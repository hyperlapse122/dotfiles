# Pi and Synthetic models

Pi is installed from complete, checksum-verified official release archives on Windows x64/ARM64, Linux x64/ARM64, and Apple Silicon. Shared external-asset preparation downloads and extracts the locked distribution once, reuses verified preparation on unchanged applies, and repairs missing installed files from its cache. The full distribution lives in `~/.local/bin/pi-native`, retaining native resources, themes, and bundled files. Direct terminal entry points are `~/.local/bin/pi` on Unix and `pi.ps1` on Windows. T3 uses the distribution's absolute native executable through its built-in Pi RPC driver.

Run `mise run apply` explicitly to install files, register the pinned native Compound Engineering package, place the pinned [korean-skills](harness-plugins.md#shared-user-scope-skills) in `~/.agents/skills`, and reconcile private Pi settings. Pi discovers those skills natively, for example as `/skill:humanizer`. Worktree preparation inventories the source without applying configuration or decrypting credentials. Close Pi and T3 before applying.

The encrypted `home/.secrets/synthetic-api-key.asc` provisions only the `synthetic` entry in private `~/.pi/agent/auth.json`. Other provider credentials remain intact. Plaintext exists only in memory during decryption and in that native private credential file; it is not exported globally or placed in tracked settings, model metadata, command arguments, or logs. The external import input remains outside the repository.

`home/.chezmoidata/synthetic-model-lock.json` defines the available model IDs, explicit capabilities, token limits, and per-million-token prices. Settings and policy consume this committed catalog through JSON serialization. Ordinary Pi startup does not discover models over the network. The application lock update workflow uses the repository Actions secret `SYNTHETIC_API_KEY` only in the dedicated resolver step, fetches the fixed HTTPS models endpoint, and stages both application and model locks in one immutable candidate. Validation consumes that pair before publication. Failed discovery retains the previous pair and fails the update job visibly.

The policy removes every foreign built-in, configured, and startup-registered provider from the effective catalog, even when foreign credentials are present. Missing Synthetic credentials and rejected Synthetic requests fail without selecting another provider. New sessions select the first sorted locked ID if the configured default disappeared. A saved session selecting a removed or foreign model reports that the saved model is unavailable; it does not silently switch models.

Run `python tests/smoke_pi.py` with the repository's tools on PATH for disposable-home native verification. Add `--t3` to verify the installed T3 server's native Pi discovery with managed binary directories absent from PATH. Hosted CI can use `--install-desktop`; provisioning is refused on personal machines. The smoke uses inert credentials and a rejecting loopback request capture. Each eligible platform must supply its own native result.
