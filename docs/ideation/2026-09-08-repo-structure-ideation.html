이 저장소는 이미 성숙합니다. 결정은 .chezmoidata/에 살고, 스크립트는 리컨실러이며, 외부 도구는 체크섬으로 고정되고, 에이전트 설정은 하나의 데이터에서 세 하네스로 펼쳐집니다. 그래서 이번 아이디에이션이 겨눈 지점은 "무엇이 빠졌는가"가 아니라 어떤 구조 규칙이 아직 관습·산문·손으로 유지되는 중이며, 그것이 언제 조용히 어긋나는가입니다. 42개 후보 중 위상 번호 체계를 재생성·재편하려는 계열은 전부 기각했습니다 — 저장소 자신의 학습이 "번호 조직은 검증됐다, 재편하지 말고 신중히 확장하라"고 명시하기 때문입니다.

Grounding Context

Codebase Context

최상위는 chezmoi 소스 상태(.chezmoi*.toml, 173줄 .chezmoiignore, .chezmoiremove)와 비배포 트리가 한 루트를 공유합니다 — 현재 최상위 항목 50개(.git 제외 49개). 데이터 계층 .chezmoidata/ 15개 파일이 facts·gating·commands·agents·fonts·system 매니페스트와 releases.json 락을 소유하고, .chezmoitemplates/ 35개 파셜이 검증자·가드·데이터 소비자 세 갈래로 나뉩니다. .chezmoiscripts/는 14개 단계 디렉터리에 73개 스크립트를 담되 분포가 심하게 치우쳐 있습니다: 30-linux 19개, 50-linux-kde 10개, 30-components 9개인 반면 20-darwin·20-linux-ubuntu·60-build·65-commands·80-keys는 각 1개입니다. .chezmoiexternals/ 6개 TOML이 약 60개 도구를 sha256/sha512로 고정하고, packages/(Bun: command-reconcile, settings-reconcile, release-lock)·crates/·system/·docs/(241개, 그중 docs/plans/에 214개가 평평하게)·.ci/(약 54개 게이트 스크립트, lib/, fixtures/, 2341줄 skip-declaration-site-matrix.yaml)가 그 옆에 섭니다.

레버리지: 약 60개 도구의 단일 병목인 릴리스 락, 렌더 시점에 스키마 드리프트를 잡는 facts-validate.tmpl, 반복 적용에서 깨끗한 chezmoi diff를 만드는 onchange 핑거프린트. 고통: 호스트 팩트가 늘 때마다 오르는 단계 간 상호의존, 렌더 시점 op 해석에서 깊숙이 실패하는 시크릿 오타, 락 바깥에서 스크립트가 소유해야 하는 자기 재작성 빌드 도구(Flutter/Android SDK).

STRATEGY.md: 주 사용자는 설정 하나를 바꿔 모든 곳에 멱등하게 안착시키는 단일 운영자. 지표는 멱등 적용의 청결성, 소유되지 않은 라이브 표면 0, 중복 지식 0, 최소 수동 단계.

Past learnings

External context

소스 상태에 담벼락을 세운다 — .chezmoiroot, 데이터로 렌더되는 ignore, 배치용 스캐폴더

chezmoi 소스 상태 전체를 home/ 아래로 옮기고 한 줄짜리 .chezmoiroot를 둡니다. 그러면 루트는 packages/·crates/·system/·docs/·.ci/가 사는 평범한 저장소 루트가 되고, .chezmoiignore는 "이건 내 것이 아니다"라고 말할 필요가 사라집니다. 남는 .chezmoiignore는 호스트별 배포 게이팅 — 실제로 잘하는 일 — 만 담고, 그 게이팅조차 호스트 프로필 데이터에서 렌더할 수 있습니다. 마지막 조각은 scripts/new 같은 스캐폴더로, 새 스크립트를 올바른 디렉터리·접두사·핑거프린트 블록·skip 스텁과 함께 만들어 줍니다.

Axis
최상위 경계
Basis
direct: .chezmoiignore는 173줄이며 첫 블록이 저장소 메타를 한 항목씩 손으로 배제합니다.

./AGENTS.md ./STRATEGY.md ./agents.lock ./mise.toml ./mise.lock ./README.md ./LICENSE ./package.json ./docs ./_artifacts ./system

같은 파일에 이미 {{- if $f.container }} 형태의 팩트 구동 배제 블록이 존재합니다 — "데이터에서 ignore를 렌더한다"는 발상의 축소판 선례가 이미 있는 셈입니다. 현재 최상위 항목은 50개(.git 제외 49개)이며, 스캐폴더에 해당하는 도구는 검색 결과 존재하지 않습니다. external: chezmoi 공식 .chezmoiroot 문서, chezmoi 이슈 #5041, sebastienrousseau/dotfiles의 REPO_LAYOUT.md.

Rationale
지금 모든 신규 최상위 파일은 잠재적 버그입니다 — .chezmoiignore 한 줄을 잊으면 저장소 내부가 실제 $HOME으로 배포되고, 이는 되돌리기 어려운 방향의 실패입니다. .chezmoiroot는 그 반복되는 경계심을 구조적 기본값으로 바꿉니다. 부인 목록의 실패 양식은 언제나 "아무도 목록에 넣을 생각을 못 한 항목"이기 때문입니다.
Downsides
거의 모든 파일을 옮기는 단일 커밋이라 git log --follow 없이는 이력이 어색해지고, 리뷰가 사실상 불가능한 디프가 됩니다. 경로를 문자열로 참조하는 .ci 게이트와 .chezmoitemplates 인클루드를 전수 조정해야 합니다. 세 조각(루트 이전 · 프로필 렌더 · 스캐폴더)은 함께 가면 강하지만 따로 떼어 단계적으로 도입할 수도 있습니다.

이미 선언된 핑거프린트 glob을 역방향 색인으로 뒤집는다

스크립트들은 이미 자신이 무엇에 의존하는지 기계가 읽을 수 있는 형태로 선언합니다 — fingerprint.tmpl에 넘기는 glob 목록이 그것입니다. 이 정방향 선언을 뒤집어 "이 데이터 파일을 고치면 어떤 스크립트가 다시 도는가"를 생성하고, 그 색인을 자재명세(BOM)처럼 씁니다. 그러면 CI가 두 가지 이상 징후를 잡을 수 있습니다: 어떤 스크립트도 소비하지 않는 고아 데이터 파일과, 존재하지 않는 경로를 가리키는 유령 선언.

Axis
데이터 · 템플릿 · 스크립트 계층 분담 (기능 응집에도 걸침)
Basis
direct: glob 선언은 균일하고 파싱 가능한 형태입니다 — "globs" (list ".chezmoidata/fonts.yaml")가 두 번, "globs" (list "system/linux/etc/udev/rules.d/**" "system/linux/etc/libinput/**")가 한 번 나타납니다. 그리고 fingerprint.tmpl은 이제 zero-match glob에 하드 실패하므로 정방향 데이터가 신뢰 가능합니다. 역방향 색인이나 고아/유령 감지 게이트는 .ci/에 존재하지 않습니다. external: MRP/PLM의 자재명세와 where-used 리포트 — 부품 하나를 바꿀 때 영향받는 조립품을 역으로 조회하는 바로 그 구조.
Rationale
이 저장소에서 가장 비싼 질문 — "이걸 바꾸면 무엇이 다시 도는가" — 은 지금 73개 템플릿을 grep해야 답할 수 있는데, 답에 필요한 데이터는 이미 선언돼 있습니다. 경쟁 후보였던 "기능별 터치포인트 레지스트리"들이 두 번째 선언 표면을 새로 만들자고 한 반면, 이 형태는 기존 선언을 재사용해 드리프트할 사본을 만들지 않습니다.
Downsides
핑거프린트 glob은 재실행 유발 의존이지 의미론적 의존의 전부는 아닙니다 — 데이터를 읽지 않고 부작용에만 의존하는 결합은 잡히지 않습니다. 색인은 생성물이므로 스스로 신선도 게이트가 필요합니다.

순서를 재생성하지 말고, 손으로 정한 번호가 유효한지 검증한다

각 스크립트가 헤더에 requires: / provides:를 선언하고, CI는 기존에 손으로 붙인 숫자 접두사가 그 그래프의 유효한 위상 정렬인지만 확인합니다. 번호를 생성하지도, 파일을 옮기지도 않습니다. 오늘 이 관계들은 잘 쓰인 주석으로만 존재하고, 그 주석은 이름 하나만 바뀌어도 조용히 낡습니다.

Axis
적용 라이프사이클 순서
Basis
direct: 순서 근거가 주석으로만 존재한다는 사실이 여러 곳에서 확인됩니다.

.chezmoiscripts/90-src/run_onchange_after_reconcile-garden.sh.tmpl:27-37 — "It must run after 10-auth's after-scripts … Placing it LAST means a hard-fail here does not abort the unrelated after-phase provisioning."

.chezmoiscripts/10-auth/run_onchange_after_auth-gitlab.sh.tmpl:37-46 — "run_after (NOT before, unlike the auth-github sibling): `glab` is fetched by .chezmoiexternals/vcs.toml into ~/.local/bin during chezmoi's FILE phase…"

external: 철도 신호의 인터로킹 경로표 — 사람이 유지하는 순번 대신 기계가 검사하는 자원 점유표를 두어, "각각은 옳지만 함께 놓으면 위험한 두 변경"을 막는 구조.

Rationale
같은 발산에서 나온 경쟁안 여럿(접두사를 메타데이터에서 생성, 단계 트리 재편, 디렉터리를 생성물로 강등)은 저장소 자신의 학습 — "숫자 조직은 검증됐다, 재편하지 말 것" — 과 정면으로 부딪혀 기각됐습니다. 검증 전용 형태는 그 제약을 지키면서도 같은 실패(이름 변경으로 낡는 순서 주장)를 막습니다. capabilities.tmpl이 이미 requires:가 해석될 대상의 절반을 제공합니다.
Downsides
73개 스크립트에 헤더를 채워 넣는 초기 비용이 실재하고, 부분 채택 상태에서는 "선언되지 않은 의존"이 여전히 보이지 않습니다. 그래프가 틀리면 검증도 틀립니다 — 검사는 선언의 성실함을 넘지 못합니다.

규칙에 ID를 주고, 게이트가 없으면 unenforced:로 등록하게 한다

구조 규칙을 하나의 레지스트리로 모읍니다. 각 규칙은 안정적인 ID, 산문 본문, 그리고 자신을 강제하는 게이트 또는 강제되지 않는 이유와 소유자를 담은 unenforced: 항목을 가집니다. 지시 코어의 해당 절은 그 레지스트리에서 생성되고, 강제되지 않는 규칙의 개수는 예산처럼 추적됩니다.

Axis

단계 번호는 "무엇이 무엇보다 먼저인가"에 답하지만, "무엇을 건너뛸 수 있는가"에는 답하지 않습니다. 각 스크립트가 bootstrap / converge / optional 계층을 선언하면 apply --tier bootstrap이 지원되는 경로가 되고, 새 호스트·컨테이너·복구 적용이 실제로 던지는 질문에 구조가 답하게 됩니다.
