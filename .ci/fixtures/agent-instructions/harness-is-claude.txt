This harness is Claude Code. Use `Read` to read a file, which is required before an edit; `Edit` for an in-place replacement; `Write` to create a file or replace it whole; `NotebookEdit` for `.ipynb` cells; `Glob` and `Grep` to search. `Bash` runs commands only and MUST NOT apply the change itself. `Bash` also runs a command in the background, and every wait on a dispatched Orca worker MUST run that way (`run_in_background: true`), never in the foreground: a foreground wait holds the turn, so a worker's message, escalation, or question is queued and reaches the run only when the command returns. The run stays idle while that wait runs, answers what arrives, and returns to waiting; only the execution mode changes, so the command MUST still be the guide's blocking wait with its explicit timeout, and the run MUST NOT poll the background command's output on a timer. Staying idle means ENDING THE TURN. This harness re-invokes the session when a background command exits or a `Monitor` event fires, so the wake-up arrives on its own. The run MUST NOT hold the turn open with filler tool calls — `true`, `sleep`, an echo, a repeated `git status`, or a re-read of the wait's own output file — and MUST NOT re-check a dispatch's state on a cadence of its own; each such call costs a full request that re-sends the whole conversation and buys nothing the notification does not already deliver. When a wake-up needs a signal the background wait does not provide, arm one `Monitor` with an until-loop over the condition and end the turn; do not arm a second watcher for a condition an existing wait already covers. The wait-form rule below governs what that command is; this paragraph governs how it runs, so both bind every wait, and the `Monitor` until-loop directed here watches a condition rather than waiting on a worker, which that rule's ban does not reach. Reading a worker's output, querying a dispatch, or narrating progress is warranted when a message actually arrives, when the run's own deadline expires, or when the run has real work to do in the meantime — never as a way to look busy while waiting. One delegation carve-out also applies here: a standing harness instruction may tell the agent not to call the Agent (Task) tool, workflows, or deep research unless the user requested it, and this file is a recognized exception source for it. When a skill, command, or workflow the user invoked by name directs a subagent dispatch, that dispatch IS user-requested — carry it out and do not stop to ask for a separate confirmation; a skill the agent selected on its own outside a mandatory workflow sequence does not qualify, and a subagent does not re-claim this carve-out for dispatches of its own. The carve-out covers only the delegation the invoked skill defines; it does not authorize unrequested subagents, workflows, or deep research for ordinary work.
