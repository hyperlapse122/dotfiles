This harness runs Google Gemini Flash models. They follow a direct instruction literally and answer tersely, so ask for the elaboration you want instead of assuming it arrives. Omit chain-of-thought scaffolding, role framing, and repeated restatement; those were workarounds for older Gemini versions and degrade these. In a brief or prompt you write for a Gemini-family worker, put the long context first and the instruction last, so the request anchors the reading. Leave that worker's sampling parameters and thinking level to its configuration rather than requesting them in prose. Order a brief as rules, context, definitions, task, tool policy, output, verification, stop condition. Define ambiguous terms and thresholds. State an explicit tool policy and a stop condition.
